# CertSentry 证书哨兵 —— 需求开发报告（PRD）

> 版本：v1.0　日期：2026-11-09　作者：个人开发者
> 一句话定位：面向中小团队和个人站长的 SSL/TLS 证书与域名到期监控平台，支持企业微信、钉钉、飞书告警，开源可自部署，同时提供在线 SaaS 演示站。

---

## 1. 背景与行业痛点

### 1.1 证书有效期被强制缩短（已核实）

2025 年 4 月 11 日，CA/Browser Forum 通过 SC-081 投票。Apple、Google、Microsoft、Mozilla 四家浏览器厂商全部赞成，证书签发方 25 票赞成、0 票反对、5 票弃权。时间表如下：

| 生效日期 | 证书最长有效期 | 域名验证（DCV）复用期 |
|---|---|---|
| 2026-03-15 之前 | 398 天 | 398 天 |
| **2026-03-15（已生效）** | **200 天** | 200 天 |
| 2027-03-15 | 100 天 | 100 天 |
| 2029-03-15 | 47 天 | 10 天 |

影响：

- 一张证书过去一年续一次，现在一年至少续两次，2029 年起一年约 8 次。
- 域名验证复用期降到 10 天后，"手动在控制台点续期"的方式基本不可行。
- 手动维护证书清单（Excel、日历提醒）的团队，出事故的概率会成倍上升。

### 1.2 免费到期提醒消失（已核实）

Let's Encrypt 于 **2025 年 6 月 4 日**停止发送证书到期提醒邮件，原因是成本（每年数万美元）、隐私（需保存数百万邮箱）和维护复杂度。官方建议用户改用第三方监控，例如 Red Sift Certificates Lite（免费监控 250 张证书）。

很多个人站长和小团队原来唯一的提醒手段因此没了。

### 1.3 现有方案的缺口

| 方案 | 不足 |
|---|---|
| Uptime Kuma 等通用监控 | 只看到期天数。不检查证书链、多 IP 节点不一致、SAN 匹配；没有资产发现 |
| Red Sift、Keyfactor、Venafi 等商业平台 | 英文界面，面向大企业，价格高；不支持企业微信、钉钉、飞书 |
| 云厂商证书服务（阿里云、腾讯云） | 只管理在本厂商购买或托管的证书，看不到其他云和自建机房的证书 |
| 自写脚本加 cron | 没有历史记录、告警去重和多人协作，写的人离职后没人维护 |

### 1.4 典型事故类型

> 以下案例投递简历前请自行查阅原始报道核对细节。

- 运营商核心网因证书过期中断（2018 年爱立信相关事故，影响英国 O2 等）。
- 协作软件因认证证书过期全球宕机（2020 年 Microsoft Teams）。
- 负载均衡的某一个节点证书没更新，导致部分用户报错、部分正常，排查困难。**本产品逐 IP 检测，专门针对这类问题。**

## 2. 目标用户与使用场景

| 用户画像 | 规模 | 核心诉求 |
|---|---|---|
| 个人站长、独立开发者 | 1~20 个域名 | 免费、配置简单、过期前收到提醒 |
| 中小企业运维 / 开发 | 20~500 个域名，多云多机房 | 统一清单、群机器人告警、多人协作、知道"谁负责哪张证书" |
| 外包 / 建站服务商 | 为多个客户维护站点 | 按客户分组，生成状态报告发给客户 |

核心场景：

1. **S1 到期预警**：证书在 30/14/7/3/1 天前分级提醒，过期后持续告警，直到恢复。
2. **S2 配置错误发现**：证书链不完整、域名不匹配、某个 IP 节点证书较旧、使用了弱算法。
3. **S3 资产发现**：通过公开 CT 日志找出"不知道的证书"，例如测试环境的子域名，或疑似仿冒钓鱼的域名。
4. **S4 团队协作**：组织内成员分工，每个域名有负责人，告警发到对应群。

## 4. 功能需求

优先级：P0 = MVP 必须有，P1 = v0.2，P2 = v0.3 或可选。

### 4.1 账号与组织（F1）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1.1 | 注册 / 登录 | 邮箱注册，激活邮件，找回密码；登录失败限流 | P0 |
| F1.2 | 组织（多租户） | 注册时自动创建个人组织；所有数据按组织隔离 | P0 |
| F1.3 | 成员与角色 | Owner / Admin / Member / Viewer 四种角色，通过邀请链接加入 | P1 |
| F1.4 | API Token | 组织级令牌，可设置只读或读写权限，只在创建时显示一次，库内存哈希 | P1 |
| F1.5 | 审计日志 | 记录增删域名、修改告警规则、成员变更等操作 | P1 |
| F1.6 | 两步验证（TOTP） | 可选开启 | P2 |

### 4.2 监控目标管理（F2）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F2.1 | 添加监控目标 | 填写域名 + 端口（默认 443），可选 SNI；支持标签、负责人、备注 | P0 |
| F2.2 | 批量导入 | 粘贴文本或上传 CSV，逐行校验并返回错误行 | P0 |
| F2.3 | 检测频率 | 默认每 6 小时一次；可选 1h / 6h / 24h；支持手动"立即检测" | P0 |
| F2.4 | 逐 IP 检测 | 解析域名的所有 A/AAAA 记录，逐个 IP 握手，发现节点间证书不一致 | P1 |
| F2.5 | 分组与标签 | 按项目或客户分组，列表可筛选、排序（剩余天数升序为默认） | P0 |
| F2.6 | 暂停 / 恢复监控 | 下线的站点可以暂停，不产生告警 | P0 |
| F2.7 | 域名注册到期 | 通过 RDAP 查询域名注册到期日，与证书一并提醒 | P2 |

**输入校验（安全需求）**：禁止监控内网、回环、链路本地等保留地址（防止 SSRF），解析后的 IP 也要校验；端口只允许常见 TLS 端口白名单或 1~65535 中排除敏感端口。

### 4.3 证书检测（F3）

每次检测产出一条检测记录，至少包含：

| 编号 | 检测项 | 判定 | 优先级 |
|---|---|---|---|
| F3.1 | 有效期 | 剩余天数；已过期 / 尚未生效 | P0 |
| F3.2 | 域名匹配 | 监控的主机名是否在 SAN 中（支持通配符） | P0 |
| F3.3 | 证书链 | 链是否完整、是否能验证到受信根 | P0 |
| F3.4 | 基本信息 | 颁发者、序列号、SHA-256 指纹、SAN 列表、密钥类型和长度、签名算法 | P0 |
| F3.5 | 弱配置 | RSA < 2048、SHA-1 签名、TLS 1.0/1.1 可协商 | P1 |
| F3.6 | 证书变更 | 指纹变化时记录"证书已更换"事件（可用于确认续期成功） | P0 |
| F3.7 | 连接错误 | DNS 失败、超时、拒绝连接、握手失败分别归类 | P0 |
| F3.8 | CAA 记录 | 查询 CAA，提示是否限制了可签发的 CA | P2 |
| F3.9 | 吊销状态 | OCSP / CRL 查询（注意 Let's Encrypt 已停止 OCSP，需降级处理） | P2 |

### 4.4 告警（F4）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F4.1 | 通知渠道 | 邮件、企业微信群机器人、钉钉群机器人（加签）、飞书群机器人（签名校验）、通用 Webhook | P0（邮件 + 1 种机器人），其余 P1 |
| F4.2 | 告警规则 | 组织默认规则：到期阈值 [30,14,7,3,1] 天；可按分组覆盖 | P0 |
| F4.3 | 告警状态机 | 正常 → 预警 → 严重 → 已恢复；同一阈值只发一次，跨阈值才再发 | P0 |
| F4.4 | 连续失败判定 | 连接类错误连续 N 次（默认 2）才告警，避免网络抖动误报 | P0 |
| F4.5 | 静默 | 对某个目标静默 X 小时或到指定时间 | P1 |
| F4.6 | 恢复通知 | 证书更换或连接恢复后发送"已恢复" | P0 |
| F4.7 | 每周摘要 | 每周一发送组织内即将到期的证书汇总 | P1 |
| F4.8 | 测试发送 | 配置渠道时一键发送测试消息 | P0 |

### 4.5 资产发现（F5，P1）

- 用户添加根域名，系统通过 CT 日志查询该域名及子域名签发过的所有证书。
- 展示"已监控 / 未监控"对比，一键把未监控的主机名加入监控。
- 发现新签发证书时提醒（可能是同事新开的站点，也可能是有人冒签）。
- **归属验证**：使用资产发现前，用户需在 DNS 添加 `_certsentry-verify.<域名>` 的 TXT 记录，防止滥用平台收集他人资产。

### 4.6 对外能力（F6，P1）

| 编号 | 功能 | 说明 |
|---|---|---|
| F6.1 | REST API | 目标增删改查、检测记录查询、手动触发检测；OpenAPI 文档 |
| F6.2 | 状态徽章 | `GET /badge/<token>.svg`，可嵌入 README，显示剩余天数 |
| F6.3 | 公开状态页 | 组织可生成一个只读公开页，展示选定域名的证书状态 |
| F6.4 | 报表导出 | CSV 导出证书清单 |

### 4.7 运营后台（F7，P0）

使用 Django Admin：查看用户、组织、目标数量、检测队列积压、失败率；封禁滥用账号。

## 5. 核心业务规则

### 5.1 告警状态机

```
            剩余天数 <= 首个阈值                剩余天数 <= 严重阈值(默认7) 或 已过期
  [OK] ───────────────────────────▶ [WARNING] ─────────────────────────────▶ [CRITICAL]
    ▲                                   │                                        │
    │        证书指纹变化且剩余天数 > 首个阈值 / 连接恢复                         │
    └──────────────────── [RECOVERED] ◀─┴────────────────────────────────────────┘
                             (发送恢复通知后回到 OK)
```

- 每个"目标 + 阈值"组合在一个证书周期内只通知一次。周期以证书指纹区分，换证书即开启新周期。
- 已过期的证书每 24 小时重复通知一次，直到恢复或被静默。
- 连接类错误单独走"不可达"状态，连续失败 N 次进入，成功 1 次退出。

### 5.2 套餐额度（SaaS 演示站）

免费使用，但需要限额防止滥用：

| 项目 | 免费额度 |
|---|---|
| 监控目标 | 每个组织 50 个 |
| 最短检测间隔 | 6 小时（自部署版不限） |
| 手动检测 | 每个目标每 10 分钟 1 次 |
| 资产发现 | 每个组织 5 个根域名，每天刷新 1 次 |
| API 调用 | 每个 Token 每分钟 60 次 |

## 6. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 单个 worker 并发检测 ≥ 50；1000 个目标一轮检测 ≤ 2 分钟；列表页 P95 < 300ms |
| 可靠性 | 检测任务失败自动重试（指数退避，最多 3 次）；调度器单实例 + 任务幂等，重复投递不重复告警 |
| 准确性 | 告警误报率 < 1%（通过连续失败判定、多次确认实现） |
| 安全 | SSRF 防护；租户隔离（所有查询强制带组织过滤，有测试覆盖）；密码 Argon2；Webhook 密钥加密存储；CSRF、XSS 默认防护 |
| 隐私 | 只存域名和证书公开信息；用户可注销并删除全部数据 |
| 可观测性 | 结构化日志；Sentry 错误追踪；Prometheus 指标（检测耗时、失败率、队列长度） |
| 可维护性 | 测试覆盖率 ≥ 80%；CI 自动跑 lint、类型检查、测试；docker-compose 一条命令启动 |
| 数据保留 | 检测记录保留 90 天，之后按天聚合；证书快照永久保留（按指纹去重） |

## 7. 核心数据模型（概要）

| 实体 | 关键字段 | 说明 |

| Channel | org, type, config(加密), is_enabled | 通知渠道 |

| Silence | target, until, reason, created_by | 静默 |
| DiscoveredName | org, root_domain, hostname, first_seen, cert_sha256, is_monitored | CT 资产发现结果 |
| ApiToken | org, name, prefix, hash, scopes, last_used_at | API 令牌 |
| AuditLog | org, actor, action, object, diff, ip, created_at | 审计日志 |

详细字段与索引设计见技术调研报告第 6 节。

## 9. 成功指标

简历需要的是**可验证的真实数据**，上线后持续记录：

- 注册用户数、真实监控域名数（剔除自己的测试数据）。
- 累计检测次数、累计发出告警数、其中"帮助用户避免过期"的次数（告警后证书被更换）。
- GitHub star、issue、外部贡献者数量；docker 镜像拉取量。
- 系统指标：检测成功率、平均检测耗时、告警延迟（从满足条件到发出通知）。

推广渠道：V2EX（分享创造节点）、掘金、少数派、宝塔论坛、Hacker News（Show HN），以及 GitHub awesome-selfhosted 列表。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 平台被用来探测他人资产 | 合规与投诉 | 证书检测只做标准握手（等同浏览器访问）；资产发现必须 DNS 验证；限额与封禁 |
| SSRF 攻击内网 | 安全事故 | 解析后校验 IP，禁止私有段；检测 worker 部署在独立网络 |
| crt.sh 不稳定或限流 | 资产发现失败 | 以 Cert Spotter API 为备选；本地缓存；失败重试 |
| 服务器 IP 被目标站点封禁 | 检测失败误报 | 区分连接错误类型；连续失败才告警；文档说明出口 IP |
| ICP 备案问题 | 国内服务器无法上线 | 使用香港 / 新加坡 VPS，无需备案 |
| 邮件进垃圾箱 | 告警不可达 | 配置 SPF、DKIM、DMARC；推荐优先用群机器人 |
| 个人精力有限 | 延期 | 严格按 MVP 范围交付，P2 功能全部延后 |
